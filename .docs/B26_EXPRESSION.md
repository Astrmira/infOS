# 表达调教与说话手册

> **适用范围**：用户批注、角色共享说话手册、后台表达学习、动态素材注入与权限清理（前端入口：「提示词 → 表达调教」，对话消息标注复用同一套服务）

---

## 1. 数据归属与作用域

| 数据 | 权威位置 | 作用域 |
| --- | --- | --- |
| 表达规则正文 | 提示词工作区 `components/expression/thinking` | 所引用的框架 |
| SelfMind 引导正文 | 提示词工作区 `components/expression/selfminding` | 内置输出约定（维护见 [B17](./B17_PROMPT_WORKSPACE.md#21-selfmind-引导)） |
| 用户批注 | `expression_marks` | 角色、来源会话、正式消息与原文修订 |
| 说话手册与历史版本 | `expression_handbooks`、`expression_handbook_versions` | 角色共享 |
| 学习与素材配置 | `expression_settings` | 角色学习开关与全局素材选项 |
| 学习任务与批次 | `expression_learning`、`expression_learning_batches` | 来源修订 |
| 编译版本与素材冷却 | `expression_turn_versions`、`expression_replies`、`expression_state` | 逻辑执行、正式消息与主线代次 |

- 主线用户消息可自动识别明确的语气纠正；侧会话通过用户主动批注产生学习来源；重复表达提示读取当前桌面会话有效正式发言，据点场景使用各自上下文边界。
- 原始批注与「对味原话」仅在来源 Thread 内选材；角色共享同一份说话手册（切换模型配置沿用同一角色数据），主线与侧线通过各自框架引用手册正文。提示词工作区仅在所引用组件齐全时将「我的预设」补入预设列表，自定义资源包按自身组件清单完成发布校验。

## 2. 批注修订、后台学习与动态注入

### 2.1 批注来源与幂等更新

- 批注保存 `source_revision`（迁移 `0033_expression_source_revision.sql` 将历史批注初始化为来源初始修订）。选材与后台学习核对消息归属、有效状态与原文修订：原文被编辑或撤回后，管理页保留批注并标为暂停态，需用户核对确认当前原文修订后再重新激活（较新原文上的旧修订同样需重新确认）。
- 同一角色、会话、消息与规范化选区的新增请求在 SQLite 即时事务内幂等更新既有批注（复用原 ID，省略正文时沿用原批注正文）；历史旧库遗留的重复记录保留供管理，选材阶段按消息与规范化选区自动去重。

### 2.2 后台学习与恢复

- 学习任务按来源指纹与修订号去重，批次固定成员（新批注进入下一批次），模型结果提交前再次核对来源有效性。进程中断后从持久批次恢复，模型调用失败按有界次数与退避延迟重试。
- 学习使用模型入口 `model.task.expression_learning`（未指派时按任务模型 → 主模型 → 环境配置回退）与模板 `tasks/expression_learning`，输出经过结构校验、置信度门槛、规则条数上限与来源校验后更新说话手册并保留版本记录。用户可在管理页手动编辑规则、查看学习进度与历史版本、回退版本或手动发起重学（学习开关与素材开关各自独立控制）。

### 2.3 上下文编译与素材筛选

- 编译器提供 `speech_handbook`，默认框架通过手册组件渲染；可编辑表达规则沿用提示词页草稿与发布流，自定义框架依自身组件引用决定发送内容，配置升级补全缺失内置资源而不改动用户布局与指派。发言前 SelfMind 引导正文独立由 `components/expression/selfminding` 承担。
- 动态本轮素材从当前可见记忆检索结果、当前 Thread 有效批注与活动记录中选取，经相关度、长度与冷却过滤后注入 `package_context`（沿用动态填充深度，Realm 场景保持独立隔离；历史正文与缓存身份由原文稳定保持）：
  - **候选排序与上限**：拉取最近更新的 `100` 条有效批注，优先近期反馈与话题相关项（已学入手册的批注不再重复携带正文），默认最多选 `3` 条反馈与 `3` 条完整短原话（反馈按预算截断）；默认总预算 `300` 字（计入外层标签，可配置 `100–1000` 字）。
  - **指纹缓存与代次重置**：同次执行的素材复用校验完整来源指纹（含有效批注、召回记忆、手册、设置与本会话回复）。编辑或删除批注即时清理该会话素材状态，原文修订变更在下一次选材时使旧缓存失效；主线编译版本绑定逻辑 Execution ID（正式发言按 `execution_id` 查回版本，侧线兼容原 pair 来源），主线清空重置后素材冷却按新代次重新起算。

## 3. 权限与数据清理

- `/api/expression` 全量接口要求管理权限，覆盖批注、手册、历史版本、学习状态、配置与编译预览；Agent 工具权限沿用既有能力门禁。
- **清理联动规则**：
  - **删除批注**：使待学习任务失效并清理所属会话素材缓存，已学出的手册规则仍保留在角色资料中供人工编辑或回退；修改批注重新建立学习依据。
  - **记忆删除/重置**：清理含正文的派生素材。
  - **清空聊天**：清理历史编译记录、会话素材与学习队列，保留角色说话手册与表达设置。
  - **恢复出厂**：在同一 SQLite 事务中清除全部表达数据与其他业务表。
