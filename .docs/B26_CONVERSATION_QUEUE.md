# 消息队列与即时交接

> **适用范围**：`desktop` Thread 的排队发送、草稿退回、即时交接与异常恢复（据点群聊与社交应用分别遵循各自批次与编排规则）

---

## 1. 用户交互与展示边界

主对话与工作区协作栏共用同一消息队列服务。执行期间输入栏保持可编辑与提交，发送按钮切换为「加入队列」并独立保留停止按钮；输入栏上方展示当前执行摘要与待发送队列，支持折叠、编辑、移除、上下调序、暂停派发或发送待排消息。中断或失败的已发送消息不会重新列入待发送队列。

- **队列显隐边界**：仅当确实存在等待派发的消息（执行期间新增排队、真正的多条排队或处于暂停状态的待发消息）时展示队列面板；单条执行中请求、首次提交尚未领取的单条消息以及断线但无待发项时均不展开面板。
- **单条项操作与草稿退回**：每条待发消息提供立即提交、退回输入栏编辑、上移、下移与删除按钮。退回编辑先在服务端原子转为 `draft` 并停止派发（保留原文、附件、识图模式与工作区材料），待输入栏确认接收后再移除服务端草稿；取回失败或关闭页面时，未确认草稿保留在服务端以供恢复。合并退回文本时保留输入栏已有内容且不生成聊天消息对。
- **简洁状态呈现**：队列状态以简短文案与图标展示（失联显示重连图标，失败显示警告图标），长篇上游异常详情记入日志。
- **即时交接**：「立即提交」将目标项移至队首并请求交接：取消正在生成的模型请求，等待已启动工具回传结果，其余未执行工具补齐未执行结果，未完成参数草稿丢弃不执行；旧回合完成持久化与资源释放后，在同一 Thread 创建正式持久消息（不采用临时覆盖指令槽）并发起携带新指令的回合。

## 2. 持久化、刷盘一致性与观察隔离

- **队列持久表与代次校验**：`conversation_queue_threads` 保存队列暂停状态与原因；`conversation_queue_items` 保存稳定提交 ID、目标 Thread / 角色、用户原始输入、附件引用、顺序、版本号、服务端确认的 `expectedGeneration` 及执行状态（旧工具检查点字段仅保留表结构兼容，启动时清空且不再写入或注入）。主线重置清理旧代次队列项并推进代次，派发前复查 `expectedGeneration`；正在退出的旧回合按自身占用身份结算，保留新代次运行资源（主侧契约见 [主侧会话](./B26_MAIN_SIDE_THREADS.md)）。
- **同步刷盘保证（`durableQueueWrite`）**：用户显式入队、原子重生成入队（`enqueueRegeneration`）、编辑、调序、删除、取回草稿与暂停事务通过 `durableQueueWrite` 在 SQLite WAL 下临时提升至 `synchronous = FULL`，确认落盘后才向前端返回成功（宿主磁盘写入报错时不确认入队）；队列内部领取、结算与启动恢复复用连接默认的 `synchronous = NORMAL` 事务。未正式派发的排队输入不进入历史或模型上下文。
- **幂等、版本并发与附件保护**：入队使用客户端 UUID 幂等；编辑、删除与调序强制校验版本号，多端过期操作返回冲突；仍被队列引用的附件受上传清理接口保护；工作区上下文在提交时捕获并在实际编译时校验文件版本与回退。每个 Thread 同时仅运行一个前台对话（且避让同 Thread 已有后台任务与 Kernel 执行），统一经 `runChatStream` 流式输出与结算。
- **观察断线与作用域隔离**：客户端观察连接断开不影响后台执行，重连后直接拉取实时 Surface 快照接收后续增量，不重发原消息。观察请求绑定当前会话、角色与读取身份，切换会话、历史变更或释放订阅时取消在途读取并丢弃迟到响应；接口返回 `NOT_FOUND` 时使失效会话退出观察、清理本地快照与窗口选择并恢复该角色有效会话。

## 3. 停止、失败恢复与并发锁

持久队列领取输入后，`runChatStream` 沿 `ConversationTurnService` 进入统一内核调度，与普通 HTTP/SSE 对话共享并发限额。Kernel 等待期间保留当前 Thread 的前台占用，停止该请求会取消对应排队执行。主线代次在准入前固定，在实际准备输入时复核。不同 Thread 可同时执行，受全局、类别和 Thread 资源键共同约束。输入的持久队列记录与已经落盘的聊天消息继续由各自权威管理。

- **停止与异常暂停**：用户停止、执行失败、循环切断或桌面操作暂停时，保留后续待发送消息并暂停队列派发，等待用户手动续发或点击「立即提交」；正在取消的旧请求未结算前不强制并行启动。
- **早期 Surface 建立与统一失败收口**：正式派发完成会话归属与附件校验并保存用户原文（或开启重生成分支）后，立即经 `onInputAccepted` 打开 `ConversationSurfaceSession` 推送首个 `surface.open` 思考帧，使前端在图片转述与并行上下文编译结束前即接入实时运行态；待 Kernel Execution 建立后绑定 `executionId`。主线按队列身份与代次创建独立输入与执行，侧线关联已有消息对；Kernel Execution 创建前失败或会话读取失败均走同一失败结算路径，发出失败 Surface（保留已落盘原文与原因）并释放运行占用与实时队列状态。
- **启动恢复与历史合成项清理**：服务启动时检查全部未结算队列项——主线依据持久 Execution 的 `completed / waiting` 状态确认完成，侧线依据有效回复消息对确认完成；其余执行中条目标记为中断，剩余未发送项保持暂停态等待处理。已移除中断项的“继续处理”入口，不创建合成续接请求或额外消息对，用户直接在输入栏发送新指令即可续接（主线待回应事项由新输入创建新执行处理）；启动时同步取消历史遗留的未发送合成续接项而不改动已有聊天消息。
- **历史变更派发锁**：主线重置、历史编辑与侧线分支回滚期间持有会话级派发锁，拒绝并发入队、调序与恢复派发（执行器异步查询完成后同样复查此锁），并在成功与失败路径释放。分支回滚同时撤销受影响的未发送项与编辑草稿，整条侧线删除连带清空队列。
